📦 MOCK API FOR FRONTEND DEVELOPMENT
================================================================================

Frontend doesn't wait for backend!

File: frontend/src/services/mockApiService.js

Example Mock Data:
```javascript
const mockOrders = {
  "ORDER-001": {
    orderId: "ORDER-001",
    metadataHash: "QmXxx123...",
    status: "CREATED",
    adminAddress: "0x0aCdc16d8fB5ac46cC309Cbe6b235BC481c91B4a",
    createdAt: new Date().toISOString(),
    blockNumber: 10081753
  }
};

export const mockApiService = {
  getOrders: async (query) => {
    await delay(500); // Simulate network
    return { orders: Object.values(mockOrders), total: 1 };
  },
  
  createOrder: async (data) => {
    const newOrder = { ...data, createdAt: new Date() };
    mockOrders[data.orderId] = newOrder;
    return { success: true, txHash: "0xabc123...", order: newOrder };
  },
  
  getOrder: async (id) => {
    return mockOrders[id] || null;
  }
};
```

When Backend Ready:
  Simply replace mock → real API endpoints
  No component changes needed!

🔗 FILE MAPPING: Backend ↔ Frontend
================================================================================

Backend provides these endpoints:
  POST /api/orders
    ↓
Frontend calls:
  services/apiService.createOrder()
    ↓
Used in components:
  CreateOrder.jsx → handleCreateOrder()

Backend API:
  GET /api/orders/:id
    ↓
Frontend:
  const order = await useOrder().getOrder(id)
    ↓
Display in:
  OrderDetail.jsx

  BlockchainEvent collection updated
    ↓
Frontend polls:
  GET /api/orders/:id/history
    ↓
Shows in:
  OrderHistory.jsx

💡 BEST PRACTICES FOR PARALLEL WORK
================================================================================

1. ✅ Communicate Frequently
   - Don't assume, ask questions
   - Share blockers immediately
   - Over-communicate better than under

2. ✅ Stick to API Contract
   - Don't change API without sync
   - Versioning if changes needed
   - Document all changes

3. ✅ Create Mock Data
   - Frontend uses mocks first
   - Backend provides sample responses
   - Makes testing faster

4. ✅ Use Version Control
   - Create feature branches
   - Pull requests reviewed
   - Keep main stable

5. ✅ Document as You Go
   - Add comments in code
   - Update API spec
   - Create Postman collection

6. ✅ Test Independently First
   - Backend: Test endpoints locally
   - Frontend: Test components locally
   - Then integrate

7. ✅ Handle Errors Together
   - Agree on error formats
   - Consistent error codes
   - Proper error messages

8. ✅ Performance from Day 1
   - Don't optimize prematurely
   - But be aware of scalability
   - Index databases, limit queries
