📋 PHASE 4: REST API ROUTES
================================================================================

[ ] 4.1 - Order Routes
    File: src/routes/orders.js
    
    Endpoints:
      GET /api/orders
        Query: ?status=CREATED&limit=10&skip=0
        Response: { orders: [...], total: number }
      
      POST /api/orders
        Body: { orderId, metadataHash, adminAddress }
        Response: { success, txHash, order }
        Calls: contract.createOrder()
      
      GET /api/orders/:orderId
        Response: { order details + history }
      
      PUT /api/orders/:orderId
        Body: { status, detailsHash }
        Response: { success, txHash }
        Calls: contract.updateOrderStatus()
      
      DELETE /api/orders/:orderId
        Response: { success, txHash }
        Calls: contract.cancelOrder()

[ ] 4.2 - Status Routes
    File: src/routes/status.js
    
    Endpoints:
      GET /api/orders/:orderId/history
        Response: { statusUpdates: [...] }
      
      GET /api/orders/:orderId/events
        Response: { blockchainEvents: [...] }

[ ] 4.3 - Statistics Routes
    File: src/routes/stats.js
    
    Endpoints:
      GET /api/stats
        Response: {
          totalOrders,
          pendingOrders,
          completedOrders,
          cancelledOrders,
          lastUpdated
        }
      
      GET /api/stats/by-status
        Response: { status -> count mapping }

[ ] 4.4 - Health Check

📋 PHASE 6: BLOCKCHAIN EVENT SYNC
================================================================================

[ ] 6.1 - Event Listener Setup
    Start listening to contract events:
      - OrderCreated
      - OrderStatusUpdated
      - OrderCancelled
      - AdminAuthorizationChanged

[ ] 6.2 - Event Handler Functions
    When OrderCreated event fires:
      1. Parse event data
      2. Check if order exists in DB
      3. If not, insert new order
      4. Save event to BlockchainEvent collection

    When OrderStatusUpdated event fires:
      1. Parse event data
      2. Update Order status in DB
      3. Add to StatusLog collection
      4. Save to BlockchainEvent

[ ] 6.3 - Sync Worker

📝 NOTES FOR BACKEND DEVELOPER
================================================================================

1. Smart Contract Details:
   - Address: 0x5663b4AF89cFBFf92A29F8cb53516B705eF055C8
   - Network: Sepolia (11155111)
   - Functions: createOrder, getOrder, updateOrderStatus, etc.
   - Events: OrderCreated, OrderStatusUpdated, OrderCancelled

2. Contract Parameters:
   - createOrder(orderId, metadataHash)
   - orderId: string (from backend, unique)
   - metadataHash: IPFS hash or JSON hash

3. Database Schema Relationships:
   - Order 1:N StatusLog
   - Order 1:N BlockchainEvent
   - Order N:1 User

4. API Response Format (Standardized):
   {
     "success": true/false,
     "data": { ... },
     "error": { code, message },
     "timestamp": ISO string
   }

5. Event Sync Process:
   - Contract emits OrderCreated event
   - Event listener catches it
   - Save to BlockchainEvent collection
   - Update Order in database
   - Frontend polls API or WebSocket to get updates

6. Error Handling Strategy:
   - Validation errors: 400
   - Unauthorized: 401
   - Not found: 404
   - Server errors: 500
   - Contract errors: 500 + detailed message

7. Blockchain Integration Best Practices:
   - Always validate addresses
   - Handle gas estimation
   - Implement retry logic
   - Log all transactions
   - Confirm before considering success

8. Database Query Optimization:
   - Use indexes on frequently queried fields
   - Limit returned fields
   - Implement pagination
   - Cache where possible

9. Security Considerations:
   - Validate all inputs
   - Don't expose private keys
   - Use environment variables
   - HTTPS in production
   - CORS properly configured
   - Rate limiting

10. Monitoring & Logging:
    - Log all API requests
    - Log blockchain interactions
    - Monitor error rates
    - Track performance metrics
